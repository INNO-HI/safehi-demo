# Feature Specification: SafeHi 인증 시스템

**Feature Branch**: `001-auth-system`
**Created**: 2026-01-05
**Status**: Draft
**Input**: 기본 레이아웃과 인증 시스템 구현 - 로그인, 회원가입, 비밀번호 찾기, 기관 인증 페이지

## Overview

SafeHi 돌봄 관리 시스템의 인증 관련 페이지를 구현합니다. 사용자가 시스템에 접근하기 위한 기본적인 인증 흐름(로그인, 회원가입, 비밀번호 찾기)과 돌봄 매니저로 활동하기 위한 기관 소속 인증 기능을 포함합니다.

### Design References

디자인 시안 기반 구현:
- 로그인 페이지: 중앙 정렬 카드 레이아웃, 이메일/비밀번호 입력, 로그인 유지 옵션
- 회원가입 페이지: 이름, 이메일(인증), 비밀번호(강도 표시), 연락처, 약관 동의
- 비밀번호 찾기 페이지: 이메일 입력으로 재설정 링크 발송
- 기관 인증 페이지: 지역/기관 선택, 직원 증빙 서류 업로드, 메모 입력

### Tech Stack

- Next.js 14 (App Router)
- TypeScript
- Tailwind CSS
- Pretendard 폰트

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 기존 사용자 로그인 (Priority: P1)

이미 계정이 있는 사용자가 이메일과 비밀번호를 입력하여 시스템에 로그인합니다. "로그인 유지" 옵션을 선택하면 세션이 유지됩니다.

**Why this priority**: 로그인은 모든 시스템 기능 접근의 진입점으로, 가장 기본적이고 필수적인 기능입니다.

**Independent Test**: 회원가입 없이도 테스트 계정으로 로그인 흐름 전체를 테스트할 수 있으며, 성공적인 로그인 시 대시보드로 이동합니다.

**Acceptance Scenarios**:

1. **Given** 유효한 계정이 존재할 때, **When** 올바른 이메일과 비밀번호를 입력하고 로그인 버튼을 클릭하면, **Then** 대시보드 페이지로 이동합니다.
2. **Given** 로그인 폼이 표시될 때, **When** 잘못된 이메일 또는 비밀번호를 입력하면, **Then** "이메일 또는 비밀번호가 올바르지 않습니다" 오류 메시지가 표시됩니다.
3. **Given** 로그인 시 "로그인 유지" 체크박스를 선택할 때, **When** 로그인에 성공하면, **Then** 브라우저를 닫아도 세션이 유지됩니다.
4. **Given** 로그인 폼이 표시될 때, **When** 이메일 형식이 잘못되면, **Then** 실시간으로 유효성 검증 오류가 표시됩니다.

---

### User Story 2 - 신규 사용자 회원가입 (Priority: P1)

새로운 사용자가 필수 정보(이름, 이메일, 비밀번호, 연락처)를 입력하고 약관에 동의하여 계정을 생성합니다. 이메일 인증을 완료해야 가입이 완료됩니다.

**Why this priority**: 회원가입 없이는 새로운 사용자가 시스템을 이용할 수 없으므로 로그인과 동등하게 중요합니다.

**Independent Test**: 처음부터 끝까지 회원가입 프로세스를 진행하여 새 계정 생성을 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 회원가입 폼이 표시될 때, **When** 모든 필수 정보를 올바르게 입력하고 약관에 동의 후 가입하기 버튼을 클릭하면, **Then** 이메일 인증 안내 메시지가 표시됩니다.
2. **Given** 이메일 입력 후 인증 버튼을 클릭할 때, **When** 유효한 이메일이면, **Then** 인증 코드가 해당 이메일로 발송됩니다.
3. **Given** 비밀번호를 입력할 때, **When** 입력 중이면, **Then** 비밀번호 강도 조건(8자 이상, 특수문자 포함, 숫자 포함)이 실시간으로 표시됩니다.
4. **Given** 비밀번호 확인 필드에 입력할 때, **When** 비밀번호와 일치하지 않으면, **Then** 불일치 오류 메시지가 표시됩니다.
5. **Given** 필수 약관 동의가 필요할 때, **When** 전체 동의를 선택하면, **Then** 모든 개별 약관 체크박스가 자동으로 선택됩니다.
6. **Given** 이미 등록된 이메일로 가입 시도할 때, **When** 가입하기 버튼을 클릭하면, **Then** "이미 사용 중인 이메일입니다" 오류가 표시됩니다.

### User Story 3 - 비밀번호 찾기/재설정 (Priority: P2)

비밀번호를 잊은 사용자가 가입 시 사용한 이메일을 입력하여 비밀번호 재설정 링크를 받습니다.

**Why this priority**: 로그인/회원가입 다음으로 사용자가 자주 필요로 하는 기능이며, 계정 접근성을 보장합니다.

**Independent Test**: 등록된 이메일로 비밀번호 재설정 링크 발송 및 새 비밀번호 설정까지 테스트 가능합니다.

**Acceptance Scenarios**:

1. **Given** 비밀번호 찾기 페이지가 표시될 때, **When** 등록된 이메일을 입력하고 재설정 링크 발송 버튼을 클릭하면, **Then** "비밀번호 재설정 링크가 발송되었습니다" 메시지가 표시됩니다.
2. **Given** 등록되지 않은 이메일을 입력할 때, **When** 재설정 링크 발송 버튼을 클릭하면, **Then** 보안상 동일한 성공 메시지가 표시됩니다(이메일 존재 여부를 노출하지 않음).
3. **Given** 재설정 링크를 이메일로 받았을 때, **When** 링크를 클릭하면, **Then** 새 비밀번호 입력 페이지로 이동합니다.
4. **Given** 로그인 페이지에서, **When** "비밀번호 찾기" 링크를 클릭하면, **Then** 비밀번호 찾기 페이지로 이동합니다.

---

### User Story 4 - 기관 소속 인증 (Priority: P3)

회원가입 완료 후 돌봄 매니저로 활동하려는 사용자가 소속 기관을 선택하고 직원 증빙 서류를 제출하여 기관 인증을 요청합니다.

**Why this priority**: 기본 인증 시스템이 완성된 후에 필요한 부가 기능으로, 매니저 권한 부여에 필요합니다.

**Independent Test**: 로그인한 사용자가 기관 인증 폼을 제출하고 승인 대기 상태가 되는 것을 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 기관 인증 페이지가 표시될 때, **When** 소속 지역(시/도, 구/군)을 선택하면, **Then** 해당 지역의 기관 목록이 드롭다운에 표시됩니다.
2. **Given** 소속 기관을 선택한 후, **When** 인증 요청하기 버튼을 클릭하면, **Then** 인증 요청이 제출되고 "관리자 승인까지 1~2 영업일 소요됩니다" 메시지가 표시됩니다.
3. **Given** 직원 증빙 서류 업로드 영역에서, **When** 파일을 드래그하거나 클릭하여 업로드하면, **Then** 업로드된 파일명이 표시됩니다.
4. **Given** 기관 인증 요청이 승인되면, **When** 다음 로그인 시, **Then** 매니저 권한이 부여된 대시보드가 표시됩니다.

---

### Edge Cases

- 로그인 실패 5회 이상 시 계정 일시 잠금 및 보안 알림 발송
- 비밀번호 재설정 링크 유효기간(24시간) 만료 시 재발급 안내
- 회원가입 중 브라우저 종료 시 입력 데이터 복구 불가 안내
- 이메일 인증 코드 유효시간(10분) 만료 시 재발송 옵션 제공
- 대용량 증빙 서류 업로드 시 파일 크기 제한(10MB) 안내
- 지원하지 않는 파일 형식 업로드 시 허용 형식(PDF, JPG, PNG) 안내
- 네트워크 오류 시 적절한 오류 메시지 표시 및 재시도 옵션

## Requirements *(mandatory)*

### Functional Requirements

**로그인**
- **FR-001**: 시스템은 이메일과 비밀번호를 통한 로그인 기능을 제공해야 합니다.
- **FR-002**: 시스템은 "로그인 유지" 옵션을 통해 세션 연장 기능을 제공해야 합니다.
- **FR-003**: 시스템은 잘못된 로그인 시도에 대해 명확한 오류 메시지를 표시해야 합니다.
- **FR-004**: 시스템은 연속 5회 로그인 실패 시 계정을 일시 잠금해야 합니다.

**회원가입**
- **FR-005**: 시스템은 이름, 이메일, 비밀번호, 비밀번호 확인, 연락처 입력 폼을 제공해야 합니다.
- **FR-006**: 시스템은 이메일 중복 검사 및 인증 기능을 제공해야 합니다.
- **FR-007**: 시스템은 비밀번호 강도를 실시간으로 표시해야 합니다(8자 이상, 특수문자, 숫자 포함).
- **FR-008**: 시스템은 이용약관 및 개인정보 처리방침 동의 기능을 제공해야 합니다.
- **FR-009**: 시스템은 전체 동의 선택 시 모든 개별 약관을 자동 선택해야 합니다.
- **FR-010**: 시스템은 연락처 형식(010-0000-0000)을 검증해야 합니다.

**비밀번호 찾기**
- **FR-011**: 시스템은 이메일 입력을 통한 비밀번호 재설정 링크 발송 기능을 제공해야 합니다.
- **FR-012**: 시스템은 보안을 위해 이메일 존재 여부를 노출하지 않아야 합니다.
- **FR-013**: 시스템은 비밀번호 재설정 링크의 유효기간을 24시간으로 제한해야 합니다.

**기관 인증**
- **FR-014**: 시스템은 시/도, 구/군 지역 선택 기능을 제공해야 합니다.
- **FR-015**: 시스템은 선택된 지역에 따른 기관 목록을 표시해야 합니다.
- **FR-016**: 시스템은 직원 증빙 서류 파일 업로드 기능을 제공해야 합니다(선택).
- **FR-017**: 시스템은 기타 메모 입력 기능을 제공해야 합니다(선택).
- **FR-018**: 시스템은 기관 인증 요청 제출 및 승인 대기 상태 표시 기능을 제공해야 합니다.

**공통**
- **FR-019**: 모든 입력 필드는 실시간 유효성 검증을 제공해야 합니다.
- **FR-020**: 모든 페이지는 일관된 디자인 시스템을 따라야 합니다(파란색 테마, 카드 레이아웃).
- **FR-021**: 시스템은 페이지 간 네비게이션(로그인↔회원가입, 로그인→비밀번호 찾기)을 제공해야 합니다.

### Key Entities

- **User**: 시스템 사용자 정보(이름, 이메일, 비밀번호, 연락처, 가입일, 인증상태)
- **Organization**: 돌봄 기관 정보(기관명, 지역, 주소)
- **OrganizationMembership**: 사용자와 기관 간의 소속 관계(사용자, 기관, 인증상태, 증빙서류, 요청일, 승인일)
- **Region**: 지역 정보(시/도, 구/군 계층 구조)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 로그인을 3번의 입력 내에 완료할 수 있어야 합니다.
- **SC-002**: 회원가입 전체 과정을 5분 이내에 완료할 수 있어야 합니다.
- **SC-003**: 비밀번호 재설정 이메일이 요청 후 1분 이내에 발송되어야 합니다.
- **SC-004**: 95%의 사용자가 첫 시도에 로그인에 성공해야 합니다.
- **SC-005**: 페이지 로딩 시간이 3초 이내여야 합니다.
- **SC-006**: 모든 폼 유효성 검증이 사용자 입력 즉시(500ms 이내) 피드백을 제공해야 합니다.
- **SC-007**: 기관 인증 요청이 정상적으로 제출되고 관리자에게 알림이 전달되어야 합니다.

## Assumptions

- 이메일 발송 서비스는 외부 서비스를 활용합니다.
- 기관 목록 데이터는 사전에 시스템에 등록되어 있습니다.
- 파일 업로드는 PDF, JPG, PNG 형식을 지원하며 최대 10MB로 제한합니다.
- 비밀번호 정책: 8자 이상, 특수문자 1개 이상, 숫자 1개 이상 포함
- 연락처 형식: 한국 휴대폰 번호 형식(010-0000-0000)
- 기관 인증 승인은 관리자가 수동으로 처리합니다.
