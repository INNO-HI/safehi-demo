## User Scenarios & Testing *(mandatory)*

### User Story 6 - 돌봄 일지 상세 조회 (Priority: P1)

구/군 관리자가 돌봄 일지 목록에서 특정 일지를 클릭하여 상세 내용을 확인하고 승인/반려 처리를 수행합니다.

**Why this priority**: 돌봄 일지 승인/반려는 관리자의 핵심 업무이며, 상세 내용 확인 없이는 적절한 판단을 내릴 수 없습니다.

**Independent Test**: 돌봄 일지 목록(/care-logs)에서 특정 일지 행을 클릭하면 상세 페이지(/care-logs/[id])로 이동하고, 방문 정보, 돌봄 내용, 특이사항, 사진 등을 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 돌봄 일지 목록에서, **When** 특정 일지 행을 클릭하면, **Then** 해당 일지의 상세 페이지(/care-logs/[id])로 이동합니다.
2. **Given** 돌봄 일지 상세 페이지에서, **When** 페이지가 로드되면, **Then** 상단에 대상자명, 상태 배지, 작성일시가 표시됩니다.
3. **Given** 돌봄 일지 상세 페이지에서, **When** 방문 정보 섹션을 확인하면, **Then** 방문 일시, 방문 유형(방문/전화), 담당 매니저, 소속 센터가 표시됩니다.
4. **Given** 돌봄 일지 상세 페이지에서, **When** 돌봄 내용 섹션을 확인하면, **Then** 건강 상태, 식사 상태, 정서 상태, 생활 환경 정보가 카드 형식으로 표시됩니다.
5. **Given** 돌봄 일지 상세 페이지에서, **When** 특이사항 섹션을 확인하면, **Then** 담당자가 작성한 특이사항 메모가 표시됩니다.
6. **Given** 돌봄 일지 상세 페이지에서, **When** 첨부 사진이 있으면, **Then** 사진 썸네일이 그리드로 표시되고 클릭 시 확대됩니다.
7. **Given** 대기중인 돌봄 일지 상세에서, **When** "승인" 버튼을 클릭하면, **Then** 상태가 "승인"으로 변경되고 목록으로 돌아갑니다.
8. **Given** 대기중인 돌봄 일지 상세에서, **When** "반려" 버튼을 클릭하면, **Then** 반려 사유 입력 모달이 표시됩니다.

### User Story 7 - 대상자 상세 정보 조회 (Priority: P1)

구/군 관리자가 대상자 관리 목록에서 특정 대상자를 클릭하여 상세 정보와 돌봄 히스토리를 확인합니다.

**Why this priority**: 대상자의 전체적인 상황을 파악해야 적절한 돌봄 서비스를 제공할 수 있으며, 긴급 상황 대응의 기반이 됩니다.

**Independent Test**: 대상자 관리 목록(/recipients)에서 특정 대상자 행을 클릭하면 상세 페이지(/recipients/[id])로 이동하고, 기본 정보, 건강 정보, 최근 방문 기록 요약을 확인할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 대상자 관리 목록에서, **When** 특정 대상자 행을 클릭하면, **Then** 해당 대상자의 상세 페이지(/recipients/[id])로 이동합니다.
2. **Given** 대상자 상세 페이지에서, **When** 페이지가 로드되면, **Then** 상단에 대상자명, 나이, 성별, 상태 배지, 아바타가 표시됩니다.
3. **Given** 대상자 상세 페이지에서, **When** 기본 정보 섹션을 확인하면, **Then** 주소, 연락처, 비상 연락처, 담당 매니저 정보가 표시됩니다.
4. **Given** 대상자 상세 페이지에서, **When** 건강 정보 섹션을 확인하면, **Then** 주요 질환, 복용 약물, 특이사항 정보가 표시됩니다.
5. **Given** 대상자 상세 페이지에서, **When** 최근 방문 요약을 확인하면, **Then** 최근 3건의 방문 기록이 카드로 표시됩니다.
6. **Given** 대상자 상세 페이지에서, **When** "전체 방문 기록" 버튼을 클릭하면, **Then** 방문 기록 페이지(/recipients/[id]/visits)로 이동합니다.
7. **Given** 대상자 상세 페이지에서, **When** "담당자 메모" 버튼을 클릭하면, **Then** 메모 페이지(/recipients/[id]/memos)로 이동합니다.
8. **Given** 대상자 상세 페이지에서, **When** "AI 정책 추천" 버튼을 클릭하면, **Then** AI 정책 추천 페이지(/recipients/[id]/policies)로 이동합니다.

### User Story 8 - 담당자 메모 관리 (Priority: P2)

구/군 관리자가 특정 대상자에 대한 담당자 메모를 조회하고 새 메모를 작성합니다.

**Why this priority**: 담당자 메모는 대상자 관리의 연속성을 위해 중요하며, 담당자 변경 시 인수인계에 활용됩니다.

**Independent Test**: 대상자 상세에서 담당자 메모 페이지로 이동하면 기존 메모 목록이 시간순으로 표시되고, 새 메모를 작성할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 대상자 상세에서, **When** "담당자 메모" 버튼을 클릭하면, **Then** 메모 페이지(/recipients/[id]/memos)로 이동합니다.
2. **Given** 메모 페이지에서, **When** 페이지가 로드되면, **Then** 기존 메모들이 최신순으로 정렬되어 표시됩니다.
3. **Given** 메모 목록에서, **When** 각 메모를 확인하면, **Then** 작성자명, 작성일시, 메모 내용이 표시됩니다.
4. **Given** 메모 페이지에서, **When** "메모 추가" 버튼을 클릭하면, **Then** 메모 입력 폼이 표시됩니다.
5. **Given** 메모 입력 폼에서, **When** 내용을 입력하고 "저장" 버튼을 클릭하면, **Then** 새 메모가 목록 상단에 추가됩니다.
6. **Given** 메모 페이지에서, **When** "돌아가기" 버튼을 클릭하면, **Then** 대상자 상세 페이지로 돌아갑니다.

### User Story 9 - 방문 기록 전체 조회 (Priority: P2)

구/군 관리자가 특정 대상자의 전체 방문 기록을 시간순으로 조회합니다.

**Why this priority**: 대상자의 돌봄 히스토리를 파악하여 돌봄 서비스의 연속성과 품질을 관리합니다.

**Independent Test**: 대상자 상세에서 방문 기록 페이지로 이동하면 모든 방문 기록이 타임라인 형식으로 표시됩니다.

**Acceptance Scenarios**:

1. **Given** 대상자 상세에서, **When** "전체 방문 기록" 버튼을 클릭하면, **Then** 방문 기록 페이지(/recipients/[id]/visits)로 이동합니다.
2. **Given** 방문 기록 페이지에서, **When** 페이지가 로드되면, **Then** 모든 방문 기록이 최신순 타임라인으로 표시됩니다.
3. **Given** 방문 기록 목록에서, **When** 각 기록을 확인하면, **Then** 방문일시, 방문 유형, 담당자, 간략한 내용 요약이 표시됩니다.
4. **Given** 방문 기록에서, **When** 특정 기록을 클릭하면, **Then** 해당 돌봄 일지 상세 페이지로 이동합니다.
5. **Given** 방문 기록 페이지에서, **When** 날짜 필터를 적용하면, **Then** 해당 기간의 방문만 표시됩니다.
6. **Given** 방문 기록 페이지에서, **When** "돌아가기" 버튼을 클릭하면, **Then** 대상자 상세 페이지로 돌아갑니다.

### User Story 10 - AI 복지 정책 추천 조회 (Priority: P3)

구/군 관리자가 특정 대상자에게 적합한 복지 정책을 AI 기반으로 추천받아 확인합니다.

**Why this priority**: AI 정책 추천은 부가 기능으로, 관리자가 대상자에게 적합한 복지 서비스를 안내하는 데 도움이 됩니다.

**Independent Test**: 대상자 상세에서 AI 정책 추천 페이지로 이동하면 대상자 상황에 맞는 복지 정책 목록이 표시됩니다.

**Acceptance Scenarios**:

1. **Given** 대상자 상세에서, **When** "AI 정책 추천" 버튼을 클릭하면, **Then** 정책 추천 페이지(/recipients/[id]/policies)로 이동합니다.
2. **Given** 정책 추천 페이지에서, **When** 페이지가 로드되면, **Then** 추천 정책 목록이 적합도 순으로 표시됩니다.
3. **Given** 정책 목록에서, **When** 각 정책을 확인하면, **Then** 정책명, 지원 내용, 적합도(%), 신청 방법이 표시됩니다.
4. **Given** 정책 목록에서, **When** 정책 카드를 클릭하면, **Then** 정책 상세 정보가 펼쳐지거나 모달로 표시됩니다.
5. **Given** 정책 추천 페이지에서, **When** "새로고침" 버튼을 클릭하면, **Then** 최신 추천 결과로 갱신됩니다.
6. **Given** 정책 추천 페이지에서, **When** "돌아가기" 버튼을 클릭하면, **Then** 대상자 상세 페이지로 돌아갑니다.

### Edge Cases (상세 페이지)

- 존재하지 않는 ID로 접근 시 404 페이지 또는 에러 메시지 표시
- 데이터 로딩 중 스켈레톤 UI 표시
- 네트워크 오류 시 재시도 버튼과 에러 메시지 표시
- 사진이 없는 돌봄 일지의 경우 사진 섹션 숨김 또는 빈 상태 표시
- 메모가 없는 경우 빈 상태 UI와 첫 메모 작성 유도
- 방문 기록이 없는 경우 빈 상태 메시지 표시
- 추천 정책이 없는 경우 적절한 안내 메시지 표시

## Requirements *(mandatory)*

### Functional Requirements

**돌봄 일지 상세 페이지 (/care-logs/[id])**
- **FR-030**: 시스템은 돌봄 일지 목록에서 행 클릭 시 해당 일지 상세 페이지로 라우팅해야 합니다.
- **FR-031**: 상단 헤더에 대상자명, 상태 배지(대기/긴급/승인/반려), 작성일시를 표시해야 합니다.
- **FR-032**: 방문 정보 섹션에 방문 일시, 방문 유형(방문/전화), 담당 매니저, 소속 센터를 표시해야 합니다.
- **FR-033**: 돌봄 내용 섹션에 건강 상태, 식사 상태, 정서 상태, 생활 환경을 카드 형식으로 표시해야 합니다.
- **FR-034**: 특이사항 섹션에 담당자 메모를 텍스트 박스로 표시해야 합니다.
- **FR-035**: 첨부 사진이 있는 경우 썸네일 그리드로 표시하고, 클릭 시 라이트박스로 확대 표시해야 합니다.
- **FR-036**: 대기중 상태일 때 "승인"과 "반려" 버튼을 표시해야 합니다.
- **FR-037**: 반려 시 반려 사유 입력 모달을 표시하고, 사유 입력 후 반려 처리해야 합니다.
- **FR-038**: "목록으로" 버튼 클릭 시 돌봄 일지 목록 페이지로 돌아가야 합니다.

**대상자 상세 페이지 (/recipients/[id])**
- **FR-039**: 시스템은 대상자 목록에서 행 클릭 시 해당 대상자 상세 페이지로 라우팅해야 합니다.
- **FR-040**: 상단에 대상자명, 나이, 성별, 상태 배지(정상/주의/긴급/미방문), 아바타를 표시해야 합니다.
- **FR-041**: 기본 정보 카드에 주소, 연락처, 비상 연락처, 담당 매니저 정보를 표시해야 합니다.
- **FR-042**: 건강 정보 카드에 주요 질환, 복용 약물, 특이사항을 표시해야 합니다.
- **FR-043**: 최근 방문 요약 섹션에 최근 3건의 방문 기록을 카드로 표시해야 합니다.
- **FR-044**: 네비게이션 버튼 영역에 "전체 방문 기록", "담당자 메모", "AI 정책 추천" 버튼을 표시해야 합니다.
- **FR-045**: "목록으로" 버튼 클릭 시 대상자 관리 목록 페이지로 돌아가야 합니다.

**담당자 메모 페이지 (/recipients/[id]/memos)**
- **FR-046**: 기존 메모를 최신순으로 정렬하여 카드 리스트로 표시해야 합니다.
- **FR-047**: 각 메모 카드에 작성자명, 작성일시, 메모 내용을 표시해야 합니다.
- **FR-048**: "메모 추가" 버튼 클릭 시 메모 입력 폼을 표시해야 합니다.
- **FR-049**: 메모 저장 시 목록 상단에 새 메모가 추가되어야 합니다.
- **FR-050**: "돌아가기" 버튼 클릭 시 대상자 상세 페이지로 돌아가야 합니다.

**방문 기록 페이지 (/recipients/[id]/visits)**
- **FR-051**: 모든 방문 기록을 최신순 타임라인 형식으로 표시해야 합니다.
- **FR-052**: 각 기록에 방문일시, 방문 유형 아이콘, 담당자명, 간략한 내용 요약을 표시해야 합니다.
- **FR-053**: 기록 클릭 시 해당 돌봄 일지 상세 페이지(/care-logs/[careLogId])로 이동해야 합니다.
- **FR-054**: 날짜 범위 필터로 특정 기간의 방문만 조회할 수 있어야 합니다.
- **FR-055**: "돌아가기" 버튼 클릭 시 대상자 상세 페이지로 돌아가야 합니다.

**AI 복지 정책 추천 페이지 (/recipients/[id]/policies)**
- **FR-056**: 추천 정책을 적합도(%) 순으로 정렬하여 카드 리스트로 표시해야 합니다.
- **FR-057**: 각 정책 카드에 정책명, 지원 내용 요약, 적합도(%), 신청 방법을 표시해야 합니다.
- **FR-058**: 정책 카드 클릭 시 상세 정보를 아코디언 또는 모달로 표시해야 합니다.
- **FR-059**: "새로고침" 버튼으로 추천 결과를 갱신할 수 있어야 합니다.
- **FR-060**: "돌아가기" 버튼 클릭 시 대상자 상세 페이지로 돌아가야 합니다.

**공통 요구사항 (상세 페이지)**
- **FR-061**: 모든 데이터는 Mock 데이터로 구현하고, 하드코딩하지 않아야 합니다.
- **FR-062**: 각 페이지에 대응하는 커스텀 훅(useCareLogDetail, useRecipientDetail, useMemos, useVisits, usePolicies)을 구현해야 합니다.
- **FR-063**: TypeScript 타입/인터페이스를 정의하여 데이터 구조를 명확히 해야 합니다.
- **FR-064**: 데이터 로딩 중 스켈레톤 UI를 표시해야 합니다.
- **FR-065**: 에러 발생 시 에러 메시지와 재시도 버튼을 표시해야 합니다.

### Key Entities (상세 페이지)

**돌봄 일지 상세 (CareLogDetail)**
- ID, 대상자명, 담당 매니저, 소속 센터, 방문 일시, 방문 유형
- 건강 상태, 식사 상태, 정서 상태, 생활 환경
- 특이사항 메모, 첨부 사진 URL 배열
- 상태(대기/긴급/승인/반려), 반려 사유, 작성일시

**대상자 상세 (RecipientDetail)**
- ID, 이름, 나이, 성별, 상태
- 주소, 연락처, 비상 연락처
- 담당 매니저 정보(이름, 연락처, 소속)
- 건강 정보(질환, 약물, 특이사항)
- 최근 방문 기록 배열

**담당자 메모 (Memo)**
- ID, 대상자 ID, 작성자명, 작성자 ID
- 메모 내용, 작성일시

**방문 기록 (Visit)**
- ID, 대상자 ID, 돌봄 일지 ID
- 방문일시, 방문 유형(방문/전화)
- 담당자명, 내용 요약

**복지 정책 (Policy)**
- ID, 정책명, 지원 내용
- 적합도(%), 신청 방법
- 자격 요건, 상세 설명

## Success Criteria *(mandatory)*

### Measurable Outcomes (상세 페이지)

- **SC-008**: 관리자가 돌봄 일지 상세에서 3초 이내에 모든 돌봄 내용을 파악할 수 있습니다.
- **SC-009**: 관리자가 5초 이내에 돌봄 일지를 승인 또는 반려 처리할 수 있습니다.
- **SC-010**: 관리자가 대상자 상세에서 5초 이내에 대상자의 전체 상황을 파악할 수 있습니다.
- **SC-011**: 관리자가 담당자 메모를 30초 이내에 작성하고 저장할 수 있습니다.
- **SC-012**: 관리자가 방문 기록에서 원하는 기간의 기록을 10초 이내에 필터링할 수 있습니다.
- **SC-013**: 모든 페이지에서 뒤로가기 버튼을 통해 2번의 클릭 이내로 상위 페이지로 이동할 수 있습니다.

## Assumptions (상세 페이지)

- 사용자는 이미 로그인되어 있는 상태로 가정합니다 (001-auth-system 인증 필요).
- 002-admin-dashboard의 목록 페이지와 컴포넌트를 재사용합니다.
- Mock 데이터는 실제 API 연동 전까지 사용되며, API 스키마와 호환되도록 설계합니다.
- AI 정책 추천은 실제 AI 연동 없이 Mock 데이터로 시뮬레이션합니다.
- 사진 라이트박스는 별도 라이브러리(예: react-image-lightbox) 또는 자체 구현을 사용합니다.
- 반려 사유 입력은 텍스트 입력으로만 처리하며, 사전 정의된 사유 선택은 추후 구현합니다.
