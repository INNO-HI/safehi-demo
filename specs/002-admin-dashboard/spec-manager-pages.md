# Feature Specification: 매니저 관리 페이지

**Feature Branch**: `002-admin-dashboard`
**Created**: 2026-01-14
**Status**: Draft
**Input**: 매니저 관리 기능 - 목록, 상세, 보고서 전체, 방문 기록 전체 페이지 프론트엔드 구현

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 매니저 목록 조회 및 필터링 (Priority: P1)

구/군 관리자가 매니저 관리 목록에서 관할 지역의 돌봄 매니저 현황을 확인하고, 상태별로 필터링하여 근무 중/휴무/퇴직 매니저를 파악합니다.

**Why this priority**: 매니저 현황 파악은 돌봄 서비스 인력 관리의 핵심이며, 업무 배분과 일정 조정의 기반이 됩니다. 목록 페이지 없이는 상세 페이지로 진입할 수 없습니다.

**Independent Test**: 매니저 관리 페이지(/managers)에 접속하면 전체 매니저 목록과 상태별 KPI가 표시되고, 상태 탭을 통해 근무 중/휴무/퇴직 매니저를 필터링할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 매니저 관리 페이지에 접속하면, **When** 페이지가 로드되면, **Then** 전체 매니저 수, 근무 중, 휴무, 퇴직 상태별 KPI 카드가 표시됩니다.
2. **Given** 매니저 목록에서, **When** "근무 중" 탭을 클릭하면, **Then** 현재 근무 중인 매니저만 필터링되어 표시됩니다.
3. **Given** 매니저 목록에서, **When** 검색창에 "김민수"를 입력하면, **Then** 해당 이름의 매니저만 필터링됩니다.
4. **Given** 매니저 목록에서, **When** 담당 동 드롭다운에서 "목동 1동"을 선택하면, **Then** 해당 동을 담당하는 매니저만 표시됩니다.
5. **Given** 매니저 목록에서, **When** 매니저 행을 클릭하면, **Then** 해당 매니저 상세 페이지(/managers/[id])로 이동합니다.
6. **Given** 매니저 목록에서, **When** "내보내기" 버튼을 클릭하면, **Then** 현재 필터링된 매니저 목록이 Excel(.xlsx) 파일로 다운로드됩니다.

### User Story 2 - 매니저 상세 정보 조회 (Priority: P1)

구/군 관리자가 특정 매니저의 상세 정보(기본 정보, 담당 업무 현황, 최근 활동)를 확인합니다.

**Why this priority**: 개별 매니저의 업무 현황과 성과를 파악하는 것은 인력 관리와 평가의 핵심입니다. 상세 페이지는 목록 다음으로 중요한 기능입니다.

**Independent Test**: 매니저 상세 페이지(/managers/[id])에 접속하면 매니저 프로필, 담당 업무 통계, 최근 보고서/방문 기록이 표시됩니다.

**Acceptance Scenarios**:

1. **Given** 매니저 상세 페이지에 접속하면, **When** 페이지가 로드되면, **Then** 매니저 아바타, 이름, 소속 센터, 연락처, 담당 동, 담당 대상자 수, 근무 상태가 표시됩니다.
2. **Given** 매니저 상세 페이지에서, **When** 업무 통계 섹션을 확인하면, **Then** 이번 달 방문 횟수, 보고서 작성 수, 승인률이 표시됩니다.
3. **Given** 매니저 상세 페이지에서, **When** 최근 보고서 섹션을 확인하면, **Then** 최근 5건의 보고서(대상자명, 작성일, 상태)가 표시됩니다.
4. **Given** 매니저 상세 페이지에서, **When** "보고서 전체보기" 버튼을 클릭하면, **Then** 해당 매니저의 전체 보고서 목록 페이지(/managers/[id]/reports)로 이동합니다.
5. **Given** 매니저 상세 페이지에서, **When** 최근 방문 기록 섹션을 확인하면, **Then** 최근 5건의 방문 기록(대상자명, 방문일, 방문 유형)이 표시됩니다.
6. **Given** 매니저 상세 페이지에서, **When** "방문 기록 전체보기" 버튼을 클릭하면, **Then** 해당 매니저의 전체 방문 기록 페이지(/managers/[id]/visits)로 이동합니다.
7. **Given** 매니저 상세 페이지에서, **When** 뒤로가기 버튼을 클릭하면, **Then** 매니저 목록 페이지로 돌아갑니다.

### User Story 3 - 매니저별 보고서 전체 목록 조회 (Priority: P2)

구/군 관리자가 특정 매니저가 작성한 모든 보고서를 조회하고 필터링합니다.

**Why this priority**: 개별 매니저의 전체 보고서 내역을 확인하는 것은 상세 페이지의 확장 기능으로, 매니저 성과 평가와 업무 검토에 필요합니다.

**Independent Test**: 매니저 보고서 전체 페이지(/managers/[id]/reports)에 접속하면 해당 매니저의 모든 보고서가 테이블로 표시되고, 상태/날짜별 필터링이 가능합니다.

**Acceptance Scenarios**:

1. **Given** 매니저 보고서 페이지에 접속하면, **When** 페이지가 로드되면, **Then** 페이지 제목에 매니저 이름이 표시되고, 전체 보고서가 테이블로 표시됩니다.
2. **Given** 매니저 보고서 목록에서, **When** 상태 탭(전체/대기중/승인/반려)을 클릭하면, **Then** 해당 상태의 보고서만 필터링됩니다.
3. **Given** 매니저 보고서 목록에서, **When** 날짜 범위를 선택하면, **Then** 해당 기간의 보고서만 표시됩니다.
4. **Given** 매니저 보고서 목록에서, **When** 보고서 행을 클릭하면, **Then** 해당 보고서 상세 페이지(/care-logs/[id])로 이동합니다.
5. **Given** 매니저 보고서 페이지에서, **When** 뒤로가기 버튼을 클릭하면, **Then** 해당 매니저 상세 페이지로 돌아갑니다.

---

### User Story 4 - 매니저별 방문 기록 전체 조회 (Priority: P2)

구/군 관리자가 특정 매니저의 모든 방문 기록을 조회하고 필터링합니다.

**Why this priority**: 매니저의 방문 이력은 업무 수행 현황 파악과 방문 일정 조정에 필요한 부가 정보입니다.

**Independent Test**: 매니저 방문 기록 페이지(/managers/[id]/visits)에 접속하면 해당 매니저의 모든 방문 기록이 테이블로 표시되고, 날짜/방문 유형별 필터링이 가능합니다.

**Acceptance Scenarios**:

1. **Given** 매니저 방문 기록 페이지에 접속하면, **When** 페이지가 로드되면, **Then** 페이지 제목에 매니저 이름이 표시되고, 전체 방문 기록이 테이블로 표시됩니다.
2. **Given** 매니저 방문 기록 목록에서, **When** 방문 유형 탭(전체/정기 방문/긴급 방문/전화 상담)을 클릭하면, **Then** 해당 유형의 방문만 필터링됩니다.
3. **Given** 매니저 방문 기록 목록에서, **When** 날짜 범위를 선택하면, **Then** 해당 기간의 방문 기록만 표시됩니다.
4. **Given** 매니저 방문 기록 목록에서, **When** 대상자명을 검색하면, **Then** 해당 대상자 방문 기록만 필터링됩니다.
5. **Given** 매니저 방문 기록 페이지에서, **When** 뒤로가기 버튼을 클릭하면, **Then** 해당 매니저 상세 페이지로 돌아갑니다.

---

### Edge Cases

- 매니저가 없는 경우(신규 시스템) 빈 상태(empty state) UI가 표시되어야 합니다.
- 매니저가 담당하는 대상자가 없는 경우 "담당 대상자 없음" 메시지가 표시되어야 합니다.
- 매니저의 보고서/방문 기록이 없는 경우 "기록 없음" 메시지가 표시되어야 합니다.
- 퇴직한 매니저의 상세 정보는 조회 가능하지만, "퇴직" 상태 배지가 명확히 표시되어야 합니다.
- 페이지네이션에서 마지막 페이지 이후로 이동 시도 시 버튼이 비활성화되어야 합니다.

## Requirements *(mandatory)*

### Functional Requirements

**매니저 목록 페이지 (/managers)**
- **FR-001**: 시스템은 KPI 카드(전체 매니저, 근무 중, 휴무, 퇴직)를 가로로 배열하여 표시해야 합니다.
- **FR-002**: 매니저를 테이블 형식으로 표시하고, 아바타/이름/소속 센터/담당 동/담당 대상자 수/이번 달 방문/상태 컬럼을 포함해야 합니다.
- **FR-003**: 상태별 탭(전체/근무 중/휴무/퇴직)으로 필터링할 수 있어야 합니다.
- **FR-004**: 검색창(이름), 담당 동 드롭다운, 소속 센터 드롭다운으로 필터링할 수 있어야 합니다.
- **FR-005**: 테이블 행 클릭 시 해당 매니저 상세 페이지로 이동해야 합니다.
- **FR-006**: 매니저 목록 내보내기 기능(Excel)을 제공해야 합니다.
- **FR-007**: 페이지네이션으로 10개씩 표시하고, 페이지당 개수를 변경할 수 있어야 합니다.

**매니저 상세 페이지 (/managers/[id])**
- **FR-008**: 매니저 프로필 섹션에 아바타(이니셜, 성별 기반 색상), 이름, 소속 센터, 연락처, 담당 동 목록, 근무 상태를 표시해야 합니다.
- **FR-009**: 담당 업무 현황 섹션에 담당 대상자 수, 이번 달 방문 횟수, 이번 달 보고서 수, 승인률을 표시해야 합니다.
- **FR-010**: 최근 보고서 섹션에 최근 5건의 보고서(대상자명, 작성일, 상태 배지)를 리스트로 표시해야 합니다.
- **FR-011**: "보고서 전체보기" 버튼 클릭 시 매니저 보고서 전체 페이지로 이동해야 합니다.
- **FR-012**: 최근 방문 기록 섹션에 최근 5건의 방문(대상자명, 방문일, 방문 유형 배지)을 리스트로 표시해야 합니다.
- **FR-013**: "방문 기록 전체보기" 버튼 클릭 시 매니저 방문 기록 전체 페이지로 이동해야 합니다.
- **FR-014**: 헤더에 뒤로가기 버튼과 매니저 이름을 표시해야 합니다.

**매니저 보고서 전체 페이지 (/managers/[id]/reports)**
- **FR-015**: 페이지 제목에 "[매니저명]님의 보고서"를 표시해야 합니다.
- **FR-016**: 보고서를 테이블 형식으로 표시하고, 대상자명/방문일/등록일/상태 컬럼을 포함해야 합니다.
- **FR-017**: 상태별 탭(전체/대기중/승인/반려)으로 필터링할 수 있어야 합니다.
- **FR-018**: 날짜 범위 선택으로 필터링할 수 있어야 합니다.
- **FR-019**: 테이블 행 클릭 시 해당 보고서(돌봄 일지) 상세 페이지로 이동해야 합니다.
- **FR-020**: 뒤로가기 버튼으로 매니저 상세 페이지로 돌아갈 수 있어야 합니다.

**매니저 방문 기록 전체 페이지 (/managers/[id]/visits)**
- **FR-021**: 페이지 제목에 "[매니저명]님의 방문 기록"을 표시해야 합니다.
- **FR-022**: 방문 기록을 테이블 형식으로 표시하고, 대상자명/방문일/방문 유형/방문 결과 컬럼을 포함해야 합니다.
- **FR-023**: 방문 유형별 탭(전체/정기 방문/긴급 방문/전화 상담)으로 필터링할 수 있어야 합니다.
- **FR-024**: 날짜 범위 선택, 대상자 검색으로 필터링할 수 있어야 합니다.
- **FR-025**: 뒤로가기 버튼으로 매니저 상세 페이지로 돌아갈 수 있어야 합니다.

**공통**
- **FR-026**: 모든 페이지는 기존 관리자 레이아웃(사이드바)을 사용해야 합니다.
- **FR-027**: 모든 데이터는 Mock 데이터로 구현하고, 하드코딩하지 않아야 합니다.
- **FR-028**: 아바타 색상은 성별에 따라 구분해야 합니다 (여성: 분홍, 남성: 파랑).

**접근성**
- **FR-029**: 최소 글자 크기 12px, 본문 14px 이상을 유지해야 합니다.
- **FR-030**: 클릭/터치 영역 최소 44x44px을 유지해야 합니다.
- **FR-031**: 텍스트 대비율 WCAG AA (4.5:1)를 준수해야 합니다.

### Key Entities

- **매니저(Manager)**: ID, 이름, 성별, 소속 센터, 연락처, 담당 동 목록, 담당 대상자 수, 이번 달 방문 횟수, 이번 달 보고서 수, 승인률, 근무 상태(근무 중/휴무/퇴직)
- **매니저 보고서(ManagerReport)**: ID, 매니저 ID, 대상자명, 방문일, 등록일, 상태(대기중/승인/반려)
- **매니저 방문 기록(ManagerVisit)**: ID, 매니저 ID, 대상자명, 방문일, 방문 유형(정기 방문/긴급 방문/전화 상담), 방문 결과

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자가 매니저 목록에서 5초 이내에 특정 매니저를 찾아 상세 페이지로 이동할 수 있습니다.
- **SC-002**: 관리자가 매니저 상세 페이지에서 3초 이내에 해당 매니저의 업무 현황(담당 대상자, 방문 횟수, 보고서 수)을 파악할 수 있습니다.
- **SC-003**: 관리자가 매니저별 보고서/방문 기록 전체 목록에서 10초 이내에 원하는 기록을 필터링하여 찾을 수 있습니다.
- **SC-004**: 40~60대 사용자가 어려움 없이 모든 텍스트를 읽고 버튼을 클릭할 수 있습니다.
- **SC-005**: 페이지 로드 시간이 2초 이내입니다.

## Assumptions

- 관리자는 이미 로그인되어 있는 상태로 가정합니다 (001-auth-system에서 구현 완료).
- Mock 데이터는 실제 API 연동 전까지 사용되며, API 스키마와 호환되도록 설계합니다.
- 매니저 상세 페이지의 레이아웃은 기존 대상자 상세 페이지와 유사한 2컬럼 구조를 따릅니다.
- 보고서 전체/방문 기록 전체 페이지는 기존 돌봄 일지 목록 페이지의 테이블 패턴을 재사용합니다.
- 매니저 CRUD(생성/수정/삭제) 기능은 이번 스펙 범위에 포함되지 않습니다 (조회만 구현).
- Excel 내보내기는 기존 대상자 관리의 내보내기 패턴을 재사용합니다.
