# Feature Specification: 관리자 대시보드

**Feature Branch**: `002-admin-dashboard`
**Created**: 2026-01-07
**Status**: Draft
**Input**: 관리자 대시보드 - 대시보드 홈, 돌봄 일지 목록, 대상자 관리 목록 페이지 프론트엔드 구현

## Clarifications

### Session 2026-01-07

- Q: 대상자 관리 내보내기 파일 형식? → A: Excel(.xlsx) 파일
- Q: 내보내기 데이터 범위? → A: 현재 필터링된 결과 (필터 없으면 전체, 필터 있으면 필터링된 데이터만)
- Q: 내보내기 포함 컬럼? → A: 대상자 이름, 주소, 담당 매니저, 최근 방문, 방문 횟수, 상태

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 대시보드 홈에서 현황 파악 (Priority: P1)

구/군 관리자가 대시보드 홈에 접속하여 오늘의 방문 현황, 대기중인 보고서, 승인 완료 건수, 담당 대상자 수 등 핵심 KPI를 한눈에 파악하고, 최근 보고서와 알림을 확인합니다.

**Why this priority**: 대시보드 홈은 관리자가 매일 가장 먼저 확인하는 페이지로, 전체 업무 현황을 빠르게 파악할 수 있어야 합니다. 긴급 상황 인지와 일상적인 업무 모니터링의 진입점입니다.

**Independent Test**: 로그인 후 대시보드 홈(/dashboard)에 접속하면 4개의 KPI 카드, 최근 보고서 5건, 알림 4건이 표시되며, 긴급 보고서는 빨간색으로 강조 표시됩니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 로그인한 상태에서, **When** 대시보드 홈에 접속하면, **Then** 오늘 방문(24건), 대기중 보고서(8건), 승인 완료(156건), 담당 대상자(89명) KPI 카드가 표시됩니다.
2. **Given** 대시보드 홈에서, **When** 최근 보고서 섹션을 확인하면, **Then** 최대 5건의 보고서가 대상자명, 담당자명, 등록 시간, 상태(대기/긴급/승인/반려)와 함께 표시됩니다.
3. **Given** 긴급 보고서가 있을 때, **When** 최근 보고서 목록에서 해당 항목을 확인하면, **Then** 주황색 경고 아이콘과 빨간 배경의 "긴급" 배지가 표시됩니다.
4. **Given** 대시보드 홈에서, **When** 알림 섹션을 확인하면, **Then** 알림 개수 배지(4개)와 함께 긴급 알림(빨간 배경)과 일반 알림이 구분되어 표시됩니다.
5. **Given** 대시보드 홈에서, **When** "전체보기" 링크를 클릭하면, **Then** 돌봄 일지 목록 페이지로 이동합니다.

### User Story 2 - 돌봄 일지 목록 조회 및 필터링 (Priority: P1)

구/군 관리자가 돌봄 일지 목록에서 모든 보고서를 조회하고, 상태/날짜/검색어로 필터링하여 원하는 보고서를 찾습니다.

**Why this priority**: 돌봄 일지 관리는 관리자의 핵심 업무로, 대기 중인 보고서 승인/반려 처리의 기반이 됩니다.

**Independent Test**: 돌봄 일지 페이지(/care-logs)에 접속하면 전체 42건의 보고서가 테이블로 표시되고, 상태 탭과 필터를 통해 원하는 보고서만 조회할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 돌봄 일지 페이지에 접속하면, **When** 페이지가 로드되면, **Then** 총 건수(1,248건)와 상태별 탭(전체/대기중/긴급/승인/반려)이 표시됩니다.
2. **Given** 돌봄 일지 목록에서, **When** "긴급" 탭을 클릭하면, **Then** 긴급 상태인 보고서 2건만 필터링되어 표시됩니다.
3. **Given** 돌봄 일지 목록에서, **When** 검색창에 "이복동"을 입력하고 검색하면, **Then** 해당 대상자의 보고서만 필터링됩니다.
4. **Given** 돌봄 일지 목록에서, **When** 날짜 범위를 "2025.01.01 - 01.04"로 설정하면, **Then** 해당 기간의 보고서만 표시됩니다.
5. **Given** 필터가 적용된 상태에서, **When** "초기화" 버튼을 클릭하면, **Then** 모든 필터가 초기화되고 전체 목록이 표시됩니다.

### User Story 3 - 돌봄 일지 일괄 처리 (Priority: P2)

구/군 관리자가 여러 보고서를 선택하여 일괄 승인, 일괄 반려, 또는 PDF 내보내기를 수행합니다.

**Why this priority**: 개별 처리보다 일괄 처리가 업무 효율성을 크게 높여주며, 다수의 보고서를 빠르게 처리해야 하는 상황에서 필수적입니다.

**Independent Test**: 돌봄 일지 목록에서 3건을 선택하면 "3건 선택됨" 배지가 표시되고, 일괄 승인/반려/PDF 내보내기 버튼이 활성화됩니다.

**Acceptance Scenarios**:

1. **Given** 돌봄 일지 목록에서, **When** 개별 체크박스로 3건을 선택하면, **Then** 헤더에 "3건 선택됨" 배지가 표시되고 선택된 행은 연한 파란 배경으로 강조됩니다.
2. **Given** 보고서가 선택된 상태에서, **When** "일괄 승인" 버튼을 클릭하면, **Then** 선택된 보고서들의 상태가 "승인"으로 변경됩니다.
3. **Given** 보고서가 선택된 상태에서, **When** "일괄 반려" 버튼을 클릭하면, **Then** 선택된 보고서들의 상태가 "반려"로 변경됩니다.
4. **Given** 보고서가 선택된 상태에서, **When** "선택 PDF 내보내기" 버튼을 클릭하면, **Then** 선택된 보고서들이 PDF로 다운로드됩니다.
5. **Given** 돌봄 일지 목록에서, **When** 헤더의 전체 선택 체크박스를 클릭하면, **Then** 현재 페이지의 모든 보고서가 선택됩니다.

### User Story 4 - 대상자 관리 목록 조회 (Priority: P1)

구/군 관리자가 대상자 관리 목록에서 전체 돌봄 대상자 현황을 확인하고, 상태별로 필터링하여 긴급/주의/미방문 대상자를 파악합니다.

**Why this priority**: 대상자 현황 파악은 돌봄 서비스 품질 관리의 핵심이며, 특히 긴급 케이스나 미방문 대상자를 빠르게 식별하는 것이 중요합니다.

**Independent Test**: 대상자 관리 페이지(/recipients)에 접속하면 892명의 대상자 목록과 상태별 KPI가 표시되고, 상태 탭을 통해 긴급/주의/미방문 대상자를 필터링할 수 있습니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 대상자 관리 페이지에 접속하면, **When** 페이지가 로드되면, **Then** 전체 대상자(892명), 이번 주 방문(847명), 긴급 케이스(3명), 주의 필요(12명), 미방문(5명) KPI가 표시됩니다.
2. **Given** 대상자 목록에서, **When** "긴급" 탭을 클릭하면, **Then** 긴급 상태인 대상자 3명만 필터링되어 표시됩니다.
3. **Given** 대상자 목록에서, **When** "미방문" 탭을 클릭하면, **Then** 7일 이상 미방문인 대상자 5명이 표시되고, 최근 방문일이 빨간색 텍스트로 강조됩니다.
4. **Given** 대상자 목록에서, **When** 대상자 행을 확인하면, **Then** 아바타(이니셜), 이름, 나이/성별, 주소, 담당 매니저, 최근 방문일, 방문 횟수, 상태가 표시됩니다.
5. **Given** 대상자 목록에서, **When** "내보내기" 버튼을 클릭하면, **Then** 현재 필터링된 대상자 목록이 Excel(.xlsx) 파일로 다운로드됩니다.
6. **Given** 필터가 적용된 상태에서, **When** "내보내기" 버튼을 클릭하면, **Then** 필터링된 대상자만 포함된 Excel 파일이 다운로드됩니다.
7. **Given** 내보내기된 Excel 파일을 열면, **When** 컬럼을 확인하면, **Then** 대상자 이름, 주소, 담당 매니저, 최근 방문, 방문 횟수, 상태 컬럼이 포함되어 있습니다.

### User Story 5 - 공통 사이드바 네비게이션 (Priority: P1)

모든 관리자 페이지에서 사이드바를 통해 다른 페이지로 쉽게 이동합니다.

**Why this priority**: 사이드바는 모든 페이지의 공통 레이아웃으로, 일관된 네비게이션 경험을 제공해야 합니다.

**Independent Test**: 어떤 관리자 페이지에서든 사이드바의 메뉴 항목을 클릭하면 해당 페이지로 이동하고, 현재 페이지 메뉴가 활성화 상태로 표시됩니다.

**Acceptance Scenarios**:

1. **Given** 관리자 페이지에서, **When** 사이드바를 확인하면, **Then** 로고(safehi), 소속 정보(양천구청, 구/군 관리자·김담당), 메뉴 6개(대시보드, 돌봄 일지, 매니저 관리, 대상자 관리, 통계/리포트, 설정), 관할 구역 정보가 표시됩니다.
2. **Given** 대시보드 홈에 있을 때, **When** 사이드바를 확인하면, **Then** "대시보드" 메뉴가 Primary 배경색���로 활성화되어 표시됩니다.
3. **Given** 사이드바에서, **When** "돌봄 일지" 메뉴를 클릭하면, **Then** 돌봄 일지 페이지(/care-logs)로 이동합니다.
4. **Given** 사이드바에서, **When** "대상자 관리" 메뉴를 클릭하면, **Then** 대상자 관리 페이지(/recipients)로 이동합니다.

### Edge Cases

- 데이터가 없는 경우 빈 상태(empty state) UI가 표시되어야 합니다.
- 네트워크 오류 시 적절한 에러 메시지가 표시되어야 합니다.
- 페이지네이션에서 마지막 페이지 이후로 이동 시도 시 버튼이 비활성화되어야 합니다.
- 필터 조합으로 결과가 0건인 경우 "검색 결과가 없습니다" 메시지가 표시되어야 합니다.
- 일괄 처리 시 선택된 항목이 없으면 버튼이 비활성화되어야 합니다.

## Requirements *(mandatory)*

### Functional Requirements

**대시보드 홈**
- **FR-001**: 시스템은 4개의 KPI 카드(오늘 방문, 대기중 보고서, 승인 완료, 담당 대상자)를 가로로 배열하여 표시해야 합니다.
- **FR-002**: 각 KPI 카드는 숫자 값, 증감 배지(+/-), 컬러 프로그레스 바를 포함해야 합니다.
- **FR-003**: 시스템은 최근 보고서 5건을 리스트로 표시하고, 각 항목에 대상자명, 담당자명, 등록 시간, 상태 배지를 포함해야 합니다.
- **FR-004**: 긴급 보고서는 주황색 경고 아이콘과 빨간 배경의 "긴급" 배지로 시각적으로 구분해야 합니다.
- **FR-005**: 알림 섹션은 긴급 알림(빨간 배경)과 일반 알림을 구분하여 표시해야 합니다.
- **FR-006**: 헤더에 현재 날짜, 마지막 업데이트 시간, 알림 ON 버튼, 프로필 아바타를 표시해야 합니다.

**돌봄 일지 목록**
- **FR-007**: 시스템은 돌봄 일지를 테이블 형식으로 표시하고, 상태/대상자/담당 종사자/소속 센터/방문 일시/등록 시간/조치 컬럼을 포함해야 합니다.
- **FR-008**: 상태별 탭(전체/대기중/긴급/승인/반려)으로 필터링할 수 있어야 합니다.
- **FR-009**: 검색창, 날짜 범위 선택, 상태 드롭다운, 동 드롭다운으로 필터링할 수 있어야 합니다.
- **FR-010**: 개별 체크박스와 전체 선택 체크박스로 보고서를 선택할 수 있어야 합니다.
- **FR-011**: 선택된 보고서에 대해 일괄 승인, 일괄 반려, PDF 내보내기 기능을 제공해야 합니다.
- **FR-012**: 선택된 행은 연한 파란 배경으로 강조되어야 합니다.
- **FR-013**: 페이지네이션으로 10개씩 보고서를 표시하고, 페이지당 개수를 변경할 수 있어야 합니다.

**대상자 관리 목록**
- **FR-014**: 시스템은 5개의 KPI 카드(전체 대상자, 이번 주 방문, 긴급 케이스, 주의 필요, 미방문)를 표시해야 합니다.
- **FR-015**: 대상자를 테이블 형식으로 표시하고, 아바타/대상자명/나이·성별/주소/담당 매니저/최근 방문/방문 횟수/상태/조치 정보를 포함해야 합니다.
- **FR-016**: 상태별 탭(전체/정상/주의/긴급/미방문)으로 필터링할 수 있어야 합니다.
- **FR-017**: 검색창, 동 드롭다운, 담당 매니저 드롭다운, 상태 드롭다운으로 필터링할 수 있어야 합니다.
- **FR-018**: 7일 이상 미방문 대상자의 최근 방문일은 빨간색 텍스트로 강조해야 합니다.
- **FR-019**: 대상자 목록 내보내기 기능을 제공해야 합니다. 내보내기는 Excel(.xlsx) 형식으로, 현재 필터링된 결과만 포함합니다.
- **FR-019a**: 내보내기 파일에는 대상자 이름, 주소, 담당 매니저, 최근 방문, 방문 횟수, 상태 컬럼이 포함되어야 합니다.
- **FR-019b**: 필터가 적용되지 않은 경우 전체 대상자가, 필터가 적용된 경우 필터링된 대상자만 내보내기됩니다.

**공통 레이아웃**
- **FR-020**: 모든 관리자 페이지에 다크 배경(#1E293B)의 사이드바를 표시해야 합니다.
- **FR-021**: 사이드바는 로고, 소속 정보, 메뉴 6개, 관할 구역 정보를 포함해야 합니다.
- **FR-022**: 현재 페이지에 해당하는 메뉴 항목은 Primary 배경색으로 활성화 표시해야 합니다.
- **FR-023**: 메뉴 클릭 시 해당 페이지로 이동해야 합니다.

**데이터 및 상태 관리**
- **FR-024**: 모든 데이터는 Mock 데이터로 구현하고, 하드코딩하지 않아야 합니다.
- **FR-025**: TypeScript 타입/인터페이스를 정의하여 데이터 구조를 명확히 해야 합니다.
- **FR-026**: 데이터 fetching 로직은 커스텀 훅 또는 서비스 레이어로 분리해야 합니다.

**접근성**
- **FR-027**: 최소 글자 크기 12px, 본문 14px 이상을 유지해야 합니다.
- **FR-028**: 클릭/터치 영역 최소 44x44px을 유지해야 합니다.
- **FR-029**: 텍스트 대비율 WCAG AA (4.5:1)를 준수해야 합니다.

### Key Entities

- **KPI 카드**: 제목, 값, 증감값, 증감 방향(증가/감소/유지), 프로그레스 바 색상
- **보고서(CareLog)**: ID, 대상자명, 담당 종사자, 소속 센터, 방문 일시, 등록 시간, 상태(대기/긴급/승인/반려)
- **대상자(Recipient)**: ID, 이름, 나이, 성별, 주소(동, 상세주소), 담당 매니저, 최근 방문일, 방문 횟수, 상태(정상/주의/긴급/미방문)
- **알림(Notification)**: ID, 제목, 내용, 시간, 긴급 여부, 링크
- **사용자(User)**: ID, 이름, 소속 기관, 역할, 관할 구역

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자가 대시보드 홈에서 3초 이내에 오늘의 핵심 현황(KPI 4개)을 파악할 수 있습니다.
- **SC-002**: 관리자가 돌봄 일지에서 10초 이내에 원하는 보고서를 필터링하여 찾을 수 있습니다.
- **SC-003**: 관리자가 일괄 처리 기능으로 10건의 보고서를 개별 처리 대비 80% 빠르게 처리할 수 있습니다.
- **SC-004**: 관리자가 대상자 관리에서 긴급/주의/미방문 대상자를 5초 이내에 식별할 수 있습니다.
- **SC-005**: 모든 페이지에서 사이드바를 통해 2번의 클릭 이내로 원하는 페이지로 이동할 수 있습니다.
- **SC-006**: 40~60대 사용자가 어려움 없이 모든 텍스트를 읽고 버튼을 클릭할 수 있습니다.
- **SC-007**: 페이지 로드 시간이 2초 이내입니다.

## Assumptions

- 관리자는 이미 로그인되어 있는 상태로 가정합니다 (001-auth-system에서 구현 완료).
- Mock 데이터는 실제 API 연동 전까지 사용되며, API 스키마와 호환되도록 설계합니다.
- 매니저 관리, 통계/리포트, 설정 페이지는 이번 스펙 범위에 포함되지 않습니다.
- PDF 내보내기는 브라우저의 인쇄 기능을 활용하거나 별도 라이브러리를 사용합니다.
- 상태 변경(승인/반려)은 Mock 데이터 레벨에서 처리되며, 실제 백엔드 연동은 추후 구현합니다.
- Excel 내보내기는 클라이언트 사이드에서 처리하며, xlsx 라이브러리(예: SheetJS)를 사용합니다.
- 향후 매니저 관리 목록 페이지에서도 동일한 내보내기 패턴(필터링된 결과를 Excel로 내보내기)을 적용합니다.
