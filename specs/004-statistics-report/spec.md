# Feature Specification: 통계/리포트 페이지

**Feature Branch**: `004-statistics-report`
**Created**: 2026-02-16
**Status**: Draft
**Input**: 관리자 대시보드의 통계/리포트 페이지 구현 (Figma UI 기반)

## Overview

SafeHi 관리자 대시보드의 통계/리포트 페이지로, 구/군 관리자가 관할 지역의 돌봄 서비스 현황을 한눈에 파악하고 분석할 수 있는 종합 대시보드입니다. KPI 지표, 추이 차트, 상세 통계, PDF 리포트 생성 기능을 제공합니다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 핵심 KPI 현황 조회 (Priority: P1)

구/군 관리자가 통계/리포트 페이지에 접속하여 선택한 월의 핵심 성과 지표(전체 대상자 수, 방문 횟수, 보고서 처리 건수, 긴급 케이스 수, 활동 매니저 수)를 확인합니다.

**Why this priority**: 관리자가 가장 먼저 확인하는 핵심 지표로, 전체 운영 상황을 즉시 파악할 수 있는 가장 기본적인 기능입니다.

**Independent Test**: 페이지 접속 시 5개의 KPI 카드가 모두 표시되고, 기간 선택 시 해당 월의 데이터로 갱신되는지 확인하여 테스트 가능합니다.

**Acceptance Scenarios**:

1. **Given** 관리자가 로그인된 상태, **When** 통계/리포트 페이지에 접속, **Then** 5개의 KPI 카드(전체 대상자, 이번 달 방문, 보고서 처리, 긴급 케이스, 활동 매니저)가 현재 월 데이터와 함께 표시됨
2. **Given** 통계/리포트 페이지에서, **When** 기간 선택 드롭다운에서 다른 월 선택, **Then** 모든 KPI 수치가 선택한 월의 데이터로 갱신됨
3. **Given** 통계/리포트 페이지에서, **When** 긴급 케이스 수가 0보다 큼, **Then** 긴급 케이스 카드가 빨간색 강조 스타일로 표시됨

---

### User Story 2 - 방문 추이 분석 (Priority: P1)

구/군 관리자가 월별 방문 추이 차트를 통해 지난 6개월 또는 1년간의 방문 횟수 변화를 파악하고 트렌드를 분석합니다.

**Why this priority**: 서비스 제공 현황의 시계열 분석은 운영 계획 수립에 필수적인 정보입니다.

**Independent Test**: 라인 차트가 올바르게 렌더링되고, 탭 전환 시 기간별 데이터가 정확히 표시되는지 확인하여 테스트 가능합니다.

**Acceptance Scenarios**:

1. **Given** 통계/리포트 페이지에서, **When** 월별 방문 추이 영역 확인, **Then** 라인 차트와 영역 그라데이션이 포함된 차트가 표시됨
2. **Given** 6개월 탭이 선택된 상태, **When** 1년 탭 클릭, **Then** 차트가 최근 12개월 데이터로 갱신됨
3. **Given** 차트가 표시된 상태, **When** 특정 데이터 포인트에 호버, **Then** 해당 월의 정확한 방문 횟수가 툴팁으로 표시됨

---

### User Story 3 - 보고서 처리 현황 분석 (Priority: P1)

구/군 관리자가 도넛 차트를 통해 보고서 처리 상태별(승인, 대기, 긴급, 반려) 분포를 파악합니다.

**Why this priority**: 보고서 처리 현황은 매니저 업무 진행 상황과 관리자 업무 부하를 파악하는 핵심 지표입니다.

**Independent Test**: 도넛 차트가 4개 상태의 비율을 정확히 표시하고, 중앙에 총 건수가 표시되는지 확인하여 테스트 가능합니다.

**Acceptance Scenarios**:

1. **Given** 통계/리포트 페이지에서, **When** 보고서 처리 현황 영역 확인, **Then** 승인/대기/긴급/반려 4가지 상태가 색상별로 구분된 도넛 차트 표시
2. **Given** 도넛 차트가 표시된 상태, **When** 차트 중앙 확인, **Then** 총 보고서 건수가 숫자로 표시됨
3. **Given** 도넛 차트가 표시된 상태, **When** 범례 확인, **Then** 각 상태별 건수와 비율이 표시됨

---

### User Story 4 - 동별 방문 현황 분석 (Priority: P2)

구/군 관리자가 관할 지역 내 동별 방문 횟수를 가로 막대 차트로 확인하여 지역별 서비스 분포를 파악합니다.

**Why this priority**: 지역별 서비스 균형 분석을 통해 자원 배분 의사결정을 지원합니다.

**Independent Test**: 가로 막대 차트가 동별 방문 횟수를 내림차순으로 표시하고, 각 막대에 수치가 표시되는지 확인하여 테스트 가능합니다.

**Acceptance Scenarios**:

1. **Given** 통계/리포트 페이지에서, **When** 동별 방문 현황 영역 확인, **Then** 가로 막대 차트가 방문 횟수 순으로 정렬되어 표시됨
2. **Given** 막대 차트가 표시된 상태, **When** 각 막대 확인, **Then** 동 이름과 방문 횟수가 명확히 표시됨
3. **Given** 막대 차트가 표시된 상태, **When** "전체보기" 링크 클릭, **Then** 전체 동 목록이 포함된 상세 페이지 또는 모달로 이동

---

### User Story 5 - 매니저 활동 순위 확인 (Priority: P2)

구/군 관리자가 테이블 형태로 매니저별 활동 실적(방문 횟수, 보고서 건수, 승인률)을 순위별로 확인합니다.

**Why this priority**: 매니저 성과 관리 및 우수 사례 파악에 필요한 정보를 제공합니다.

**Independent Test**: 테이블에 상위 매니저 목록이 순위와 함께 표시되고, 1~3위에 메달 아이콘이 표시되는지 확인하여 테스트 가능합니다.

**Acceptance Scenarios**:

1. **Given** 통계/리포트 페이지에서, **When** 매니저 활동 순위 영역 확인, **Then** 순위, 매니저명, 방문 횟수, 보고서 건수, 승인률 컬럼이 포함된 테이블 표시
2. **Given** 테이블이 표시된 상태, **When** 1~3위 행 확인, **Then** 금/은/동 메달 스타일의 순위 표시가 있음
3. **Given** 테이블이 표시된 상태, **When** "전체보기" 링크 클릭, **Then** 전체 매니저 순위가 포함된 상세 페이지 또는 모달로 이동

---

### User Story 6 - 대상자 상태 분포 확인 (Priority: P2)

구/군 관리자가 돌봄 대상자의 상태별(정상, 주의, 긴급, 미방문) 분포와 전월 대비 변화 추이를 확인합니다.

**Why this priority**: 대상자 상태 분포는 서비스 품질과 긴급 대응 필요성을 판단하는 핵심 지표입니다.

**Independent Test**: 4가지 상태별 인원수, 비율, 전월 대비 변화가 모두 표시되는지 확인하여 테스트 가능합니다.

**Acceptance Scenarios**:

1. **Given** 통계/리포트 페이지에서, **When** 대상자 상태 분포 영역 확인, **Then** 정상/주의/긴급/미방문 4가지 상태의 인원수와 비율이 표시됨
2. **Given** 상태 분포가 표시된 상태, **When** 전월 대비 변화 영역 확인, **Then** "+24명 정상 전환", "-2명 긴급 해제" 등 변화 트렌드가 표시됨
3. **Given** 긴급 상태 인원이 있는 경우, **When** 긴급 카드 확인, **Then** 빨간색 강조 스타일로 표시됨

---

### User Story 7 - PDF 리포트 생성 (Priority: P2)

구/군 관리자가 선택한 월의 통계 데이터를 PDF 형식의 리포트로 생성하여 다운로드합니다.

**Why this priority**: 정기 보고 및 외부 공유를 위한 문서화 기능은 관리자의 핵심 업무를 지원합니다.

**Independent Test**: "리포트 생성" 버튼 클릭 시 PDF 파일이 생성되고 다운로드되는지 확인하여 테스트 가능합니다.

**Acceptance Scenarios**:

1. **Given** 통계/리포트 페이지에서, **When** 헤더의 "리포트 생성" 버튼 클릭, **Then** PDF 생성이 시작되고 로딩 상태가 표시됨
2. **Given** PDF 생성이 완료된 상태, **When** 다운로드 완료, **Then** 선택한 월의 통계 데이터가 포함된 PDF 파일이 다운로드됨

---

### User Story 8 - 빠른 리포트 생성 (Priority: P3)

구/군 관리자가 4가지 사전 정의된 템플릿(월간 종합, 매니저 실적, 대상자 현황, 긴급 케이스) 중 선택하여 특정 목적의 리포트를 빠르게 생성합니다.

**Why this priority**: 다양한 용도의 리포트를 효율적으로 생성할 수 있는 편의 기능입니다.

**Independent Test**: 4개의 템플릿 카드가 표시되고, 각 "생성" 버튼 클릭 시 해당 템플릿의 리포트가 생성되는지 확인하여 테스트 가능합니다.

**Acceptance Scenarios**:

1. **Given** 통계/리포트 페이지에서, **When** 빠른 리포트 생성 영역 확인, **Then** 4가지 템플릿 카드(월간 종합, 매니저 실적, 대상자 현황, 긴급 케이스)가 표시됨
2. **Given** 템플릿 카드가 표시된 상태, **When** "월간 종합 리포트" 카드의 "생성" 버튼 클릭, **Then** 방문/보고서/대상자 현황이 포함된 리포트 생성 시작
3. **Given** 템플릿 카드가 표시된 상태, **When** "긴급 케이스 리포트" 카드의 "생성" 버튼 클릭, **Then** 긴급/주의 대상자 목록이 포함된 리포트 생성 시작

---

### Edge Cases

- 선택한 월에 데이터가 없는 경우 어떻게 표시할 것인가? (빈 상태 표시 및 안내 메시지)
- 차트 데이터 로딩 중 오류 발생 시 어떻게 처리할 것인가? (오류 메시지 및 재시도 버튼)
- PDF 생성 실패 시 어떻게 처리할 것인가? (오류 알림 및 재시도 안내)
- 매니저가 한 명도 활동하지 않은 동이 있는 경우 동별 현황에서 어떻게 표시할 것인가? (0회로 표시)
- 동시에 여러 PDF를 생성하려고 할 경우 어떻게 처리할 것인가? (이전 생성 완료 후 진행 또는 큐잉)

## Requirements *(mandatory)*

### Functional Requirements

#### 페이지 레이아웃 및 헤더
- **FR-001**: 시스템 MUST 통계/리포트 페이지를 `/admin/statistics` 경로로 제공해야 함
- **FR-002**: 페이지 MUST 기존 관리자 대시보드 레이아웃(사이드바, 헤더)을 재사용해야 함
- **FR-003**: 페이지 헤더 MUST "통계/리포트" 제목과 부제목 "양천구 돌봄 서비스 현황 분석"을 표시해야 함
- **FR-004**: 헤더 MUST 월 단위 기간 선택 드롭다운을 제공해야 함 (형식: "YYYY년 MM월")
- **FR-005**: 헤더 MUST "리포트 생성" 버튼을 제공해야 함

#### KPI 카드 영역
- **FR-006**: 시스템 MUST 5개의 KPI 카드를 가로로 배열하여 표시해야 함
- **FR-007**: KPI 카드 MUST 다음 항목을 포함해야 함:
  - 전체 대상자 (파랑 아이콘)
  - 이번 달 방문 (초록 아이콘)
  - 보고서 처리 (노랑/주황 아이콘)
  - 긴급 케이스 (빨강 아이콘)
  - 활동 매니저 (보라 아이콘)
- **FR-008**: 각 KPI 카드 MUST 레이블, 수치, 구분 아이콘을 표시해야 함
- **FR-009**: 긴급 케이스 카드 MUST 값이 0보다 클 때 빨간색 강조 스타일을 적용해야 함

#### 차트 영역
- **FR-010**: 월별 방문 추이 차트 MUST 라인 차트와 영역 그라데이션으로 표시되어야 함
- **FR-011**: 월별 방문 추이 MUST "6개월" / "1년" 탭 전환 기능을 제공해야 함
- **FR-012**: 차트 MUST X축에 월, Y축에 방문 횟수를 표시해야 함
- **FR-013**: 차트 데이터 포인트 호버 시 MUST 해당 월의 정확한 수치를 툴팁으로 표시해야 함
- **FR-014**: 보고서 처리 현황 MUST 도넛 차트로 표시되어야 함
- **FR-015**: 도넛 차트 MUST 승인/대기/긴급/반려 4가지 상태를 색상으로 구분해야 함
- **FR-016**: 도넛 차트 중앙 MUST 총 건수를 표시해야 함
- **FR-017**: 도넛 차트 MUST 범례에 각 상태별 건수와 비율을 표시해야 함

#### 상세 통계 영역
- **FR-018**: 동별 방문 현황 MUST 가로 막대 차트로 표시되어야 함
- **FR-019**: 동별 방문 막대 차트 MUST 방문 횟수 순으로 내림차순 정렬되어야 함
- **FR-020**: 각 막대 MUST 동 이름과 방문 횟수를 표시해야 함
- **FR-021**: 동별 방문 현황 MUST "전체보기" 링크를 제공해야 함
- **FR-022**: 매니저 활동 순위 MUST 테이블 형태로 표시되어야 함
- **FR-023**: 매니저 테이블 MUST 순위, 매니저명, 방문 횟수, 보고서 건수, 승인률 컬럼을 포함해야 함
- **FR-024**: 1~3위 매니저 MUST 금/은/동 색상의 메달 스타일 또는 배지로 구분 표시되어야 함
- **FR-025**: 매니저 활동 순위 MUST "전체보기" 링크를 제공해야 함

#### 하단 영역
- **FR-026**: 대상자 상태 분포 MUST 정상/주의/긴급/미방문 4가지 상태별 인원수와 비율을 표시해야 함
- **FR-027**: 대상자 상태 분포 MUST 각 상태별 색상 구분을 제공해야 함 (정상: 초록, 주의: 노랑, 긴급: 빨강, 미방문: 회색)
- **FR-028**: 대상자 상태 분포 MUST 전월 대비 변화 트렌드를 표시해야 함 (예: "+24명 정상 전환", "-2명 긴급 해제")
- **FR-029**: 빠른 리포트 생성 MUST 4가지 템플릿 카드를 제공해야 함:
  - 월간 종합 리포트 (방문, 보고서, 대상자 현황)
  - 매니저 실적 리포트 (방문 횟수, 승인률 분석)
  - 대상자 현황 리포트 (상태별, 지역별 분포)
  - 긴급 케이스 리포트 (긴급/주의 대상자 목록)
- **FR-030**: 각 템플릿 카드 MUST "생성" 버튼을 포함해야 함

#### 리포트 생성 기능
- **FR-031**: 헤더의 "리포트 생성" 버튼 클릭 시 MUST 선택한 월의 전체 통계 PDF를 생성해야 함
- **FR-032**: 빠른 리포트 템플릿의 "생성" 버튼 클릭 시 MUST 해당 유형의 PDF를 생성해야 함
- **FR-033**: PDF 생성 중 MUST 로딩 상태를 표시해야 함
- **FR-034**: PDF 생성 완료 시 MUST 파일을 자동 다운로드해야 함

#### 데이터 및 상태 관리
- **FR-035**: 기간 선택 변경 시 MUST 페이지 내 모든 데이터를 선택한 월 기준으로 갱신해야 함
- **FR-036**: 데이터 로딩 중 MUST 각 영역별로 로딩 상태를 표시해야 함
- **FR-037**: 데이터가 없는 경우 MUST 빈 상태 UI와 안내 메시지를 표시해야 함
- **FR-038**: 데이터 로딩 오류 시 MUST 오류 메시지와 재시도 버튼을 표시해야 함

### Key Entities

- **KPI 데이터**: 전체 대상자 수, 월간 방문 횟수, 보고서 처리 건수, 긴급 케이스 수, 활동 매니저 수
- **방문 추이 데이터**: 월별 방문 횟수 시계열 데이터 (6개월/12개월)
- **보고서 현황 데이터**: 상태별(승인/대기/긴급/반려) 건수 및 비율
- **동별 방문 데이터**: 동 이름, 방문 횟수
- **매니저 활동 데이터**: 매니저명, 방문 횟수, 보고서 건수, 승인률, 순위
- **대상자 상태 데이터**: 상태별(정상/주의/긴급/미방문) 인원수, 비율, 전월 대비 변화
- **리포트 템플릿**: 템플릿 유형, 제목, 설명, 아이콘

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 페이지 로딩 후 2초 이내에 모든 KPI 카드와 차트가 표시되어야 함
- **SC-002**: 기간 선택 변경 후 1초 이내에 모든 데이터가 갱신되어야 함
- **SC-003**: 관리자가 원하는 통계 정보를 3번 이내의 클릭/스크롤로 찾을 수 있어야 함
- **SC-004**: PDF 리포트 생성이 10초 이내에 완료되어야 함
- **SC-005**: 차트와 수치가 정확히 일치하여 데이터 신뢰도 100%를 유지해야 함
- **SC-006**: 40~60대 사용자가 모든 텍스트와 차트를 쉽게 읽을 수 있어야 함 (최소 글자 크기 12px, 본문 14px 이상)
- **SC-007**: 페이지 내 모든 클릭/터치 영역이 최소 44x44px 크기를 유지해야 함

## Assumptions

- 기존 관리자 대시보드 레이아웃(사이드바, 헤더)이 이미 구현되어 있음
- 백엔드 API가 별도로 존재하며, 프론트엔드는 Mock 데이터로 먼저 구현 후 API 연동 예정
- 차트 라이브러리로 recharts를 사용 (이미 설치되어 있거나 설치 예정)
- PDF 생성은 클라이언트 사이드에서 처리하거나 백엔드 API를 통해 처리
- "전체보기" 링크의 구체적인 동작(모달 vs 별도 페이지)은 기존 패턴을 따름
- 사이드바에 "통계/리포트" 메뉴 항목이 이미 있거나 추가 필요

## Out of Scope

- 실시간 데이터 업데이트 (WebSocket 등)
- 차트 데이터 내보내기 (Excel, CSV)
- 커스텀 기간 선택 (날짜 범위 직접 지정)
- 차트 필터링/드릴다운 기능
- 알림/알람 설정 기능
- 다국어 지원
